# Phase 5 clean-room and provenance record

Date: 2026-08-13

Phase 5 introduced no new SurrealQL behavior and used no SurrealDB source,
tests, fixtures, expected output, fuzz corpus, or implementation detail. It
hardened the independently authored Phase 1-4 contract with FastDB-specific
cache, malformed-input, model, injection, JSON, CLI, fixture, crash,
filesystem, fuzz, and benchmark evidence.

The parser and structured CRUD fuzz targets and every `P5-*` expected result
were authored from FastDB's public `COMPAT.md`, format document, API contract,
and storage invariants. The committed `.fastdb` fixtures were generated by
FastDB at Phase 4 commit `932f90ce5`; only the migration fixture's
`last_migration` catalog integer was changed from 1 to 0 using the pinned
Turso CLI. SHA-256 digests and the exact provenance are kept beside them.

The native Turso benchmark path is not compatibility research. It uses the
pinned engine as FastDB's storage baseline with equivalent physical values,
durability, indexing, worker serialization, and result materialization.

The behavioral reference remains the already documented unmodified
SurrealDB `v3.1.5` black-box/public-document work under
`docs/compat-research/`. No compatibility row changed status in Phase 5.
