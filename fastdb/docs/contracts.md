# Embedded alpha contracts (format 1, not a V1 release)

Full V1 scope remains defined in the parent FastDB.md and FastQL.md plans. This implementation is an initial persistent slice; the list below is not a reduction of release scope.

Values at the Rust boundary distinguish null, boolean, int64, finite float64, string, binary, record, object, array, and opaque vector bytes. Objects are sorted maps. A stored value is `FDB` followed by byte `01`, then UTF-8 JSON of a fully tagged value tree (`type`/`value` at every node). User objects are nested inside an Object tag, so arbitrary keys cannot masquerade as records. Rust serde_json preserves int64 exactly. This internal format is not yet a cross-language wire contract: JavaScript transport must encode integers losslessly before bindings ship. Vector bytes have no validated public construction contract yet.

Collection names and record targets use ASCII case folding, consistent with SQL name lookup. Integer keys and string keys remain distinct. Full documents contain a typed immutable id. UUIDv7 string keys are generated by the engine when id is omitted. Missing fields are absent from the object; explicit null is retained. Nesting is limited to 64. References validate shape and target, not existence.

Every document statement uses an engine SAVEPOINT, including catalog and index changes. Errors roll back the statement; an outer transaction remains usable unless the engine itself aborts it. A failed rollback returns FDB_ROLLBACK with both errors. Multi-statement input is not accepted by execute. BEGIN/COMMIT/ROLLBACK use the same connection for SQL and document operations.

Indexes use real engine tables and B-tree indexes, maintained transactionally. The key column has no affinity: integers and floats compare numerically, booleans index as 0/1, strings remain strings, null/missing do not conflict in unique indexes. Index creation validates all stored values before metadata publication. Rust lookup_index joins indexed IDs to stored documents in one snapshot. Automatic SQL predicate planning over logical collections is pending.

The initial Rust error categories have stable identifiers exposed by code(). Engine errors currently retain their native message in FDB_ENGINE; constraint/busy/cancellation subcategories need definition before V1. SELECT/RETURNING produce rowsets with all/first/exactly_one helpers; a collection document occupies one Object-valued column named document. Commands without RETURNING have no rows. Ordinary SQL columns retain engine names, types, and positional ordering. Final duplicate-column and client/wire contracts remain release gates.

General SQL over logical collections is currently rejected. A conservative token guard also rejects references to managed storage/catalog names, including quoted names. This is a temporary incomplete compatibility boundary, not the final SQL authorizer: some harmless strings are rejected. Replace it with AST-aware logical lowering and dependency authorization before claiming ordinary SQL preservation or enabling all write paths. Do not expose raw engine connection handles through FastDB.
