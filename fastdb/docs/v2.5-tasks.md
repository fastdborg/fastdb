# FastDB 2.5.0: spatial upgrade and faster document paths

User-authorized 2026-10-13: implement the open items of the spatial upgrade and
release them as the next minor version. Linux x64; all seven existing native
clients. Previous artifacts stay immutable. Contract:
[spatial-upgrade.md](spatial-upgrade.md); evidence:
[spatial-upgrade-evidence.md](spatial-upgrade-evidence.md) and
[the SurrealDB comparison](spatial-surrealdb-comparison.md).

## Spatial upgrade (plan milestones S0–S4)

- [x] Polygon and MultiPolygon values, strict GeoJSON exchange, exact
  point-in-region predicates and `ST_*` aliases ([checklist](spatial-upgrade-tasks.md)).
- [x] H3 boundary, hierarchy, disk, distance, area and compaction functions.
- [x] Two-dimensional Morton index format with a covering B-tree; catalog version 7;
  `REINDEX` upgrade of latitude-format indexes.
- [x] `search::bbox`, `search::polygon`, `search::nearest` and ordinary SQL index use
  for region, radius and nearest-with-filter forms.
- [x] Region indexes for stored zones (`WITH (geometry = 'region')`) with
  `search::containing` and indexed `ST_Covers(shape, point)`.
- [x] Ordinary rewrites use a semijoin on the stored ID column and replace exactly
  equivalent conditions instead of re-evaluating them per row.
- [x] Profile counters `spatial_ranges` and `spatial_rounds` (Node `spatialRanges`,
  `spatialRounds`).

## Document path performance

- [x] Field accessors read one field from the stored encoding instead of decoding
  the whole document; fallback to full decoding for any non-canonical layout.
- [x] Faster nesting pre-scan for stored values.
- [x] Updates and deletes maintain scalar and point-index entries by key, and skip
  entries whose key did not change, instead of scanning the entry table by ID.
- [x] One stack segment per operation instead of one per statement preparation.
- [x] Document import inserts inside its own savepoint without one savepoint and one
  catalog read per document.
