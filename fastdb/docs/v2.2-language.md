# FastQL 2.2.0 language contracts

Working specifications, 2026-10-01. Only entries with linked passing evidence
are implemented. Release/client qualification is tracked in [the checklist](v2.2-tasks.md).
Preserve the 2.1.0 catalog and protocol unless a feature explicitly versions it.

## Ordinary SELECT reference wildcard

Implemented in source; focused and full scoped checks pass. Release artifact
qualification remains pending. See [nested projections](nested-projections.md) and
[working evidence](v2.2-tasks.md). The single-field aliased wildcard uses the
existing bounded resolver and contributes one positional column.

## S1: OMIT (implementation pending)

Initial form:

```sql
SELECT * OMIT embedding, internal_notes, profile.private FROM articles
WHERE published = true ORDER BY id LIMIT 20;
```

This returns the ordinary collection `document` column with the named object
members removed. The source must be one collection. Explicit projections,
joins, relational sources and source-star aliases are rejected in this initial
form rather than choosing which output object to alter. Identifiers and quoted
keys follow existing SQL rules. Paths address the returned document, not source
aliases. Dot paths traverse embedded objects only; a missing member, null or
scalar intermediate value is a no-op. Arrays and references are not traversed
implicitly. Duplicate/overlapping paths are harmless and order-independent.
`id` can be omitted from the result without changing the stored record identity.

Filtering, ordering and pagination read the original document. Omission does
not write data, change validation/indexes, or provide access control. Preserve
typed values in retained fields and enforce result limits on returned values.
Input query, path and value nesting bounds continue to apply. Bound parameters
remain values, and cannot provide omitted field identifiers.

The [SurrealQL SELECT reference](https://surrealdb.com/docs/reference/query-language/statements/select)
documents the same placement of OMIT and nested field examples. FastDB retains
its one-object positional result and object-only paths; destructuring and
array traversal require their own contracts. Comparison checked 2026-10-01;
no claim of complete SurrealQL compatibility.

## S3: CONTENT replacement (implementation pending)

Planned forms target one fixed record or the matched documents of a collection:

```sql
UPDATE articles:a CONTENT {title: 'Replacement', author: writers:w1} RETURNING *;
UPDATE articles CONTENT $document WHERE author = writers:w1 RETURNING id;
```

CONTENT replaces all user fields, including whole nested objects and arrays.
It preserves the target's immutable typed ID. An explicit payload ID must equal
that target's ID, otherwise the statement fails. A missing target is not
inserted. Required fields, checks, unique constraints and every index kind apply
to the full replacement. All matched documents and indexes share one statement
savepoint; evaluation, validation, output-limit or cancellation failure rolls
back the statement while preserving earlier caller work. Bound object values
retain their logical types. Every candidate is evaluated against its original
document before mutations begin.

Existing `UPDATE collection { ... }` and `UPDATE collection:key { ... }` keep
their shallow-patch meaning. A new MERGE spelling must specify recursive object
merge if adopted: it cannot silently alias the existing shallow update.
The [SurrealQL UPDATE reference](https://surrealdb.com/docs/reference/query-language/statements/update)
documents whole-object CONTENT and recursive MERGE. FastDB keeps RETURNING and
typed positional results. Future read-only validation must reject replacement
that changes or removes a read-only field; it must not silently bypass checks.

## S5: helper audit (implementation pending)

The current typed helper catalog has `array::new`, `array::append`, `doc::get`,
and `doc::has`, but no typed distinct/flatten or object keys/entries/construction
helper. Engine JSON helpers cannot replace these where records, binary, vectors
and 64-bit integers must remain typed. Implement shared pure-value functions for
SQL projections and document write expressions, without host I/O or closures.
Document deterministic ordering, duplicate keys, type errors and resource bounds.
Reference: [SurrealQL object functions](https://surrealdb.com/docs/reference/query-language/functions/database-functions/object),
reviewed 2026-10-01.
