# FastQL 2.2.0 language contracts

Working specifications, 2026-10-01. Only entries with linked passing evidence
are implemented. Release/client qualification is tracked in [the checklist](v2.2-tasks.md).
Preserve the 2.1.0 catalog and protocol unless a feature explicitly versions it.

## Ordinary SELECT reference wildcard

Implemented in source; focused and full scoped checks pass. Release artifact
qualification remains pending. See [nested projections](nested-projections.md) and
[working evidence](v2.2-tasks.md). The single-field aliased wildcard uses the
existing bounded resolver and contributes one positional column.

## S1: OMIT (source qualified; release qualification pending)

The focused record-projection suite passes all 15 tests, including three OMIT
regressions. Combined scoped Rust, Node/TypeScript and C ABI checks pass;
exact release artifacts and all-client qualification remain pending.

Initial form:

```sql
SELECT * OMIT embedding, internal_notes, profile.private FROM articles
WHERE published = true ORDER BY id LIMIT 20;
```

This returns the ordinary collection `document` column with the named object
members removed. The source must be one collection. Explicit projections,
joins, relational sources and source-star aliases are rejected in this initial
form rather than choosing which output object to alter. Identifiers and quoted
keys follow existing SQL rules. Paths address the returned document, not source
aliases. Dot paths traverse embedded objects only; a missing member, null or
scalar intermediate value is a no-op. Arrays and references are not traversed
implicitly. Duplicate/overlapping paths are harmless and order-independent.
`id` can be omitted from the result without changing the stored record identity.

Filtering, ordering and pagination read the original document. Omission does
not write data, change validation/indexes, or provide access control. Preserve
typed values in retained fields and enforce result limits on returned values.
Input query, path and value nesting bounds continue to apply. Bound parameters
remain values, and cannot provide omitted field identifiers.
At most 1,024 omission paths, each with at most 64 steps, are accepted. RETURNING
does not accept this SELECT clause. Result bounds count retained values; decoding
the source document still requires memory for the original contents.

The [SurrealQL SELECT reference](https://surrealdb.com/docs/reference/query-language/statements/select)
documents the same placement of OMIT and nested field examples. FastDB retains
its one-object positional result and object-only paths; destructuring and
array traversal require their own contracts. Comparison checked 2026-10-01;
no claim of complete SurrealQL compatibility.

## S3: CONTENT replacement and recursive MERGE (source qualified)

Forms target one fixed record or the matched documents of a collection:

```sql
UPDATE articles:a CONTENT {title: 'Replacement', author: writers:w1} RETURNING *;
UPDATE articles CONTENT $document WHERE author = writers:w1 RETURNING id;
UPDATE articles:a MERGE {profile: {country: 'FR'}} RETURNING *;
```

CONTENT replaces all user fields, including whole nested objects and arrays.
It preserves the target's immutable typed ID. An explicit payload ID must equal
that target's ID, otherwise the statement fails. A missing target is not
inserted. Required fields, checks, unique constraints and every index kind apply
to the full replacement. All matched documents and indexes share one statement
savepoint; evaluation, validation, output-limit or cancellation failure rolls
back the statement while preserving earlier caller work. Bound object values
retain their logical types. Every candidate is evaluated against its original
document before mutations begin.
Fixed targets do not accept an additional WHERE; use a collection predicate for
conditional updates. The existing affected-count and RETURNING conventions apply.

Existing `UPDATE collection { ... }` and `UPDATE collection:key { ... }` keep
their shallow-patch meaning. MERGE combines nested objects recursively when both
values are objects. Incoming arrays, scalars and null replace that entire value;
unmentioned members remain. Neither form uses null to mean removal.
The [SurrealQL UPDATE reference](https://surrealdb.com/docs/reference/query-language/statements/update)
documents whole-object CONTENT and recursive MERGE. FastDB keeps RETURNING and
typed positional results. Future read-only validation must reject replacement
that changes or removes a read-only field; it must not silently bypass checks.

Focused evidence: 13 parser tests; 79 existing/new write tests, seven metered
write tests and 13 write-buffer tests; three CONTENT/MERGE regressions include
all index kinds, failure after a successful mutation prefix, caller work,
concurrent-reader snapshots and reopen. Combined scoped checks and sync/async
Node regressions pass. Exact release artifact qualification remains pending.

## S4: typed PATCH (source qualified; release qualification pending)

```sql
UPDATE articles:a PATCH [
  {op: 'test', path: '/status', value: 'draft'},
  {op: 'replace', path: '/status', value: 'published'},
  {op: 'add', path: '/tags/-', value: 'release'}
] RETURNING *;
```

PATCH accepts an array of add, remove, replace, copy, move and test operations.
The expression is evaluated against the original document; operations execute
in order on the candidate. The same fixed-record/collection WHERE targeting,
immutable ID, validation, statement savepoint and RETURNING rules as CONTENT
apply. Copy/test preserve exact logical types: integer and floating-point values
are distinct, record table names compare case-insensitively, object member order
is irrelevant, and arrays remain ordered. Null is a value; missing is an error.
Records, binary and vectors are opaque values, not traversable containers.

Member paths use [JSON Pointer](https://www.rfc-editor.org/rfc/rfc6901) escaping
(`~0` for tilde and `~1` for slash). Empty member names are supported. Parents
must exist. Object add may insert or replace; replace/remove require the member.
Array indices are canonical nonnegative integers without leading zeroes; add
inserts before that position and accepts `-` to append. Move removes the source
before resolving its destination and rejects a parent-to-descendant move.
Unknown operation members are ignored. Operation names are case-sensitive.

This is a bounded typed member-operation subset of
[JSON Patch](https://www.rfc-editor.org/rfc/rfc6902), not complete RFC or
SurrealQL PATCH compatibility. Empty/root pointers are rejected: use CONTENT
for whole-document replacement and DELETE for removal. ID and its descendants
cannot be destinations or move sources; copying or testing the ID is allowed.
The nonstandard text-diff `change` operation is not supported.

Limits per candidate: 1,024 operations, 64 pointer steps, 16 KiB per pointer,
one million operation/traversal/array-shift steps, and 64 MiB cumulative tagged
value bytes across input, copy sources and intermediate documents. Existing
64-level value nesting and statement candidate/result/work bounds also apply.
These deterministic work bounds are not a process heap guarantee. Failure at
any stage discards all candidate changes and rolls back all affected indexes.

## S5: typed array/object helpers (source qualified; release qualification pending)

The current typed helper catalog has `array::new`, `array::append`, `doc::get`,
and `doc::has`, but no typed distinct/flatten or object keys/entries/construction
helper. Engine JSON helpers cannot replace these where records, binary, vectors
and 64-bit integers must remain typed. Added shared pure-value functions for
SQL expressions and document write expressions, without host I/O or closures:

| Function | Contract |
| --- | --- |
| `array::len(array)` | Number of immediate elements as an int64. |
| `array::distinct(array)` | Retain first occurrences in input order using exact logical type equality. Record targets compare case-insensitively and integer/string keys differ. Integers and floats differ; floating-point signed zeroes compare equal. Objects compare by key/value pairs, arrays by ordered elements. |
| `array::flatten(array)` | Flatten exactly one array level, preserving order and non-array elements. |
| `doc::keys(object)` | String member names in deterministic UTF-8 lexical order. |
| `doc::values(object)` | Typed values in the same key order. |
| `doc::entries(object)` | `[key, value]` pairs in that key order. |
| `doc::from_entries(array)` | Build an object from two-element `[string, value]` pairs. Duplicate keys and malformed pairs are errors. |

Each takes exactly one argument of the declared type. Null and missing input
are type errors, not empty containers. Stored null members remain present;
absent members are not invented. Existing `doc::has` distinguishes their presence
while `doc::get` returns null for either. Empty arrays/objects remain valid.
Use `array::new(...)` or bound values for SQL array construction, preserving
SQLite bracket-quoted identifiers.
FastDB uses the already reserved `doc::` namespace for object helpers. It does
not reserve or override the previously user-defined `object::` namespace when
opening an existing database; this is a deliberate spelling difference from
SurrealQL.

Materializing helpers accept at most 100,000 immediate input and output items;
`array::len` only counts and does not impose that item limit. All helpers bound
combined tagged input/output bytes to 64 MiB and enforce existing value depth.
Distinct uses hashed canonical typed encodings, not pairwise quadratic scans.
Retained values preserve the first occurrence's record spelling and float bits.
These helpers do not create indexes or imply an indexed array search.
Reference: [SurrealQL object functions](https://surrealdb.com/docs/reference/query-language/functions/database-functions/object),
reviewed 2026-10-01.

## S2: FETCH implementation design (not implemented yet)

The existing deferred projection resolver can support whole-document expansion
without an engine callback or a new storage format. Adopt a bounded initial
`SELECT * FROM articles ... FETCH author, metadata.editor` form, with FETCH last
after WHERE/ORDER BY/LIMIT. Require a single collection and a whole-document
result; explicit projections, joins, derived sources and combination with OMIT
need separate composition rules. Preserve ordinary SQL uses of `fetch` as a
table, field or alias.

Expand only explicitly named finite paths in the returned document. Traverse
embedded objects and arrays, resolve a typed record when that named path reaches
it, and preserve other members. Duplicate/overlapping paths must be independent
of list order. A missing field stays missing, a missing referenced record becomes
null, and ordinary scalar values remain values. Cyclic references terminate at
the supplied path depth; no recursive wildcard or graph semantics. Filtering,
sorting and pagination use stored values before expansion. Target reads and
source reads must share a snapshot and the resolver's batching, deduplication,
reference/work/byte limits. No change to stored references or index contents.

The [FETCH reference](https://surrealdb.com/docs/reference/query-language/clauses/fetch)
was reviewed on 2026-10-01. FastDB's key distinction is returning one positional
document column whose selected members are expanded, rather than adding or
overwriting positional columns. Exact tests and delivery qualification remain.
