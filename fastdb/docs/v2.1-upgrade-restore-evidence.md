# V2.0-to-V2.1 upgrade and restore qualification

Development checkout rehearsal passed on 2026-09-25, using Node 24.19.0 on
Ubuntu 24.04 Linux x64 under WSL2. This is **not final optimized artifact
qualification**. The [rehearsal receipt](v2.1-upgrade-rehearsal.json) records
executed addon and immutable backup hashes. The candidate came from the Rust
development profile with uncommitted 2.1 changes; its addon SHA-256 is
`2a5b7695e150356166e914f6ea8037b1d3745f516b6075c55047ff6a863959ea`.

The old writer is the actual published 2.0.0 Node package. Its native and
JavaScript files were verified byte-for-byte against the public bundle with
SHA-256 `614744deed4e24f91f14e5ccdb331b07edf743fae04eafda963fa9b7d6c4d006`.
The harness requires package version 2.0.0 and pins those four runtime-file
hashes; changing package.json alone cannot substitute another writer.

`fastdb/scripts/check-v21-upgrade.cjs` runs each phase in a separate process.
It rejects existing output directories, copies with exclusive creation, and
never loads the old and new native libraries in the same VM. The fixture uses
`synchronous=FULL`. Every source copy follows a successful truncating checkpoint,
zero-length WAL check and closed process/handles.

The old writer creates relational rows and a view, required/CHECK validation,
unique/nested/reference indexes, typed documents with int64 limits, binary64 edge
values, binary data, arrays and references, indexed FTS/ANN/spatial search,
bounded inverse lookups, exact migration history and persisted JavaScript
functions. Independent old-version exports and inspection metadata become the
candidate's baseline expectations.

The candidate opens the database, verifies all baseline values and indexed
queries, tests a multi-index mutation/delete rollback, commits new relational
and indexed document writes, checkpoints and reopens in another process. Stored
function source/signature/digest survive unchanged while `INFO FOR FUNCTION`
reports the patched runtime. A persisted function with the published QuickJS
rope-indentation trigger returns the correct JSON after upgrade. The new finite
`posts.*.*` projection fetches previously stored typed references.

The harness restores the candidate backup into a fresh file, verifies queries,
rollback and committed new writes after another reopen, then rechecks the
original candidate source. It separately restores the untouched 2.0 backup,
verifies it using the original 2.0 binary, and upgrades that restored copy with
2.1. Both original backup hashes remain unchanged. This proves backup restoration
with the appropriate binary; it makes no promise that 2.0 can open files written
by 2.1.

The bundle verifier requires an explicit `--v2-package` argument and runs this
harness against the exact installed candidate package on both required Node
runtimes. Those receipts are separate from this development rehearsal and must
pass before release. Example direct invocation:

```sh
node fastdb/scripts/check-v21-upgrade.cjs \
  /absolute/published-2.0.0/package \
  /absolute/candidate-2.1.0/package \
  /absolute/new-rehearsal-directory
```
