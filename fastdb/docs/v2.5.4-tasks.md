# FastDB 2.5.4: fastdb:// URLs and fewer client round trips

User-authorized 2026-10-15: release the client changes merged in PR 24 as 2.5.4
so Studio and Cloud users can use `fastdb://` connection URLs. Linux x64; all
seven native clients. The engine, catalog format and service protocol are
unchanged; previous artifacts stay immutable.

## Clients

- [x] Node client and CLI accept `fastdb://` as an alias for `https://`; the same
  URL checks apply, so a token, credentials or a query string are still refused.
- [x] Node `connect({ deferInfo: true })` on a Cloud database URL skips the
  details request; `prepareWrite` refuses to guess an unknown sequence.
- [x] CLI `db access` reuses the previous reply's sequence when that write was
  the only commit and was confirmed within 2 s; otherwise it fetches as before.

## Dependencies

- [x] rustls 0.23.45 → 0.23.46 (CLI only, through reqwest): RustSec published
  four rustls advisories on 2026-10-14 (RUSTSEC-2026-0346 to 0349), all fixed
  in 0.23.46. No other package changes; license texts are unchanged.

## Release

- [x] Full scoped checks on the version-aligned source: 1,095 Rust, 187 Node, five C ABI,
  two release-policy and three upgrade-table tests; four opt-in measurement tests
  are ignored by design.
- [x] Notices and RustSec review (359 shipping packages, zero unresolved findings).
- [x] Upgrade dry run (ten checks on Node 22 and 24), exact-source CI, production
  bundle and all 39 installed verification groups, including 2.5.3 → 2.5.4.
- [ ] Release records, tag `fastdb-v2.5.4` on the build commit, publication and

Cloud keeps the 2.5.3 engine image: the engine is unchanged.
