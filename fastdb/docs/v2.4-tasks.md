# FastDB 2.4.0: graph tables and traversal

User-authorized 2026-10-12: implement [the graph plan](../../../plan-graph.md),
release it as the next minor version, and update Cloud and Studio for graph use.
Linux x64; all seven existing native clients. Previous artifacts stay immutable.
Contract: [graph.md](graph.md).

## Engine (plan milestones G0–G5)

- [x] Parser: `CREATE EDGE TABLE`, `RELATE`, and the `GRAPH(...)` body with
  directions, step filters, `DEPTH`, `MODE` and `WITH PATH`.
- [x] Catalog version 6 edge metadata, endpoint dependencies and a permanent graph
  marker that makes 2.3.0 and older refuse the file.
- [x] Mandatory outgoing/incoming adjacency storage, schema audit, INFO and DROP rules.
- [x] Shared edge mutation hooks: endpoint existence and type, immutable endpoints,
  CONTENT/PATCH preservation, UNSET rejection, OR REPLACE endpoint comparison.
- [x] RESTRICT and CASCADE deletion policies on every node deletion path.
- [x] MVCC endpoint write so a concurrent endpoint delete conflicts (race test fails
  without it); WAL single-writer serialization covered by the same test.
- [x] Fixed paths, three directions, step filters, typed path arrays and SQL composition.
- [x] Bounded REACHABLE (shortest distance, deterministic witness) and PATHS (simple paths).
- [x] Statement limits with `FDB_LIMIT`, verified adjacency index seeks, EXPLAIN rows
  without traversal, profile counters, shared snapshot and pending writes.
- [x] Integrity audit compares adjacency with edges and endpoints.
- [x] Service/Cloud request classification: RELATE is a metered write, CREATE EDGE
  TABLE a checked schema statement, GRAPH sources metered reads.
